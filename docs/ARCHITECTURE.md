# Архитектура

```
Claude Desktop ──stdio (MCP)──► autocad-mcp-server.exe ──named pipe──► AutocadMcp.Plugin.dll ──► AutoCAD .NET API
 (вызовы с подтверждением)       src/AutocadMcp.Server       (только текущий        внутри acad.exe          (одна транзакция
                                                             пользователь)          src/AutocadMcp.Plugin     на вызов)
                                         └────────── общие правила: src/AutocadMcp.Core ──────────┘
```

## Части

| Проект | Где работает | Что делает |
| --- | --- | --- |
| `AutocadMcp.Core` | везде | Протокол канала (`Protocol/`), модель запросов и проверка (`Model/`), `PathGuard` и имена (`Safety/`), журнал (`Audit/`), настройки (`Settings/`), список инструментов (`ToolNames.cs`). AutoCAD не нужен, всё покрыто тестами. |
| `AutocadMcp.Plugin` | внутри AutoCAD 2025 | `PluginApp` запускается при старте AutoCAD. `PipeHost` слушает канал. `MainThreadDispatcher` переносит работу в главный поток AutoCAD. `ToolRouter` выбирает обработчик. `Handlers/` — сами действия. `Commands` — `MCPSTATUS`/`MCPSTOP`/`MCPSTART`/`MCPLOG`. |
| `AutocadMcp.Server` | отдельный процесс, его запускает Claude Desktop | MCP по stdio (официальный SDK). `Tools/AutocadTools.cs` — описания инструментов для Claude. `PipeClient` пересылает вызов в AutoCAD. `--smoke` — самопроверка. |

## Путь одного вызова

1. Claude вызывает `build_drawing` с JSON, человек подтверждает его в Claude Desktop.
2. Сервер отправляет `PipeRequest { protocol, id, tool, args }` по каналу (4 байта длины + UTF-8 JSON, не больше 4 МБ).
3. `PipeHost` проверяет версию протокола и что действие есть в `ToolNames`, затем ставит работу в очередь главного потока (тайм-аут 60 с).
4. В главном потоке `ToolRouter` проверяет: чертёж открыт, AutoCAD не занят командой. Блокирует документ и вызывает обработчик.
5. Обработчик целиком проверяет запрос (`SpecValidator`) и выполняет его одной транзакцией.
6. Ответ уходит обратно. Строка пишется в командную строку AutoCAD и в журнал.

## Почему так

- **Надстройка внутри AutoCAD, а не COM снаружи:** быстрее, есть транзакции и проверка, нет зависимости от COM.
- **Named pipe, а не HTTP/TCP:** нет открытого порта, доступ ограничен пользователем Windows.
- **Один пакетный `build_drawing`, а не сотни мелких вызовов:** быстро, одно подтверждение, одна отмена.
- **Проверка в надстройке, а не в сервере:** надстройка — последняя линия обороны, она не доверяет никому, даже своему серверу.
- **Самодостаточный exe:** коллегам не нужен .NET.
