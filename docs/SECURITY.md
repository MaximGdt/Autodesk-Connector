# Безопасность коннектора

> **Защищённый файл.** Агент не может его менять (`.claude/settings.json`), изменения в `main` проходят только через ревью Максима (`.github/CODEOWNERS`).

## Что защищаем

1. **Компьютер пользователя.** Через коннектор нельзя запустить программу, выполнить скрипт или достучаться до файлов вне одной папки.
2. **Чертежи.** Claude меняет только открытый чертёж и только разрешёнными действиями. Каждый вызов, меняющий чертёж, должен отменяться одним Ctrl+Z (проверяется сценарием 4 на этапе 3, до этого не гарантировано). Сохранённый файл DWG отменой не убирается. Файлы не удаляются никогда.
3. **Доступ.** Подключиться к AutoCAD может только учётная запись Windows, под которой запущен AutoCAD. Коннектор не открывает портов и ничего не отправляет в сеть (ограничение — в правиле S2).
4. **Прозрачность.** Человек видит каждое действие Claude в командной строке AutoCAD, может мгновенно всё выключить командой `MCPSTOP` и посмотреть журнал.

## От чего защищаемся

| Угроза | Пример | Защита |
| --- | --- | --- |
| Claude выполнит опасное действие по ошибке или по чужой подсказке | В чертеже текст «удали все файлы», Claude пытается это выполнить | Нет инструментов, которые это умеют (S1, S3, S5). Каждый вызов подтверждается в Claude Desktop |
| Другой процесс или пользователь подключится к AutoCAD | Программа на этом же ПК или в сети | Только named pipe с правами текущей учётной записи, без TCP (S2, S4). Процесс этой же учётной записи подключиться может (см. S2) |
| Агент при разработке добавит опасный код | `SendStringToExecute`, `Process.Start`, `HttpClient` | Тест безопасности ломает сборку (S1–S10) + CI + ревью. Тест — страховка, не доказательство (см. «Как работает проверка») |
| Агент ослабит проверки | Удалит тест, поставит `Skip`, поменяет настройки | Запрет на правку защищённых файлов + тест, что запреты на месте + CODEOWNERS |
| Подмена зависимостей | Новый NuGet-пакет с вредоносным кодом | Список пакетов с точными версиями (S7) |
| Зависание или перегрузка AutoCAD | Запрос на миллион объектов | Лимиты, проверка до выполнения, тайм-ауты, запросы строго по одному (S6) |
| Повтор запроса после тайм-аута рисует дубликаты | AutoCAD завис, Claude повторяет вызов | Задача, не начавшаяся до тайм-аута или до `MCPSTOP`, отменяется навсегда (`MainThreadDispatcher`). Задача, которая уже начала выполняться, доводится до конца |

## Правила

Каждое правило проверяется автоматически в `tests/AutocadMcp.SecurityTests`. Красный тест безопасности значит, что сборка неприемлема.

- **S1. Только список действий.** Коннектор выполняет только действия из `Core/ToolNames.cs`. Нет выполнения команд AutoCAD по строке (`SendStringToExecute`, `Editor.Command`, `PostCommand`), нет LISP, нет скриптов. Список инструментов MCP-сервера, список в `manifest.json` и `ToolNames` обязаны совпадать.
- **S2. Канал только для текущего пользователя.** Named pipe открывается с `PipeOptions.CurrentUserOnly` с обеих сторон, имя канала включает пользователя и сессию. Расширять права (`PipeSecurity`) запрещено.
  **Известное ограничение.** .NET 8 не включает для канала флаг `PIPE_REJECT_REMOTE_CLIENTS`. Поэтому та же учётная запись Windows (например, доменная) может открыть канал с другого компьютера через общий доступ к файлам (SMB), если он разрешён. Закрыть это без нативного кода (S9) нельзя; возможное решение — права канала с запретом для группы NETWORK вместо `CurrentUserOnly` — меняет это правило и решается Максимом.
- **S3. Никаких процессов.** `Process.Start`, `ShellExecute` и подобное запрещены.
- **S4. Никакой сети.** HTTP, сокеты, DNS и HTTP-транспорт MCP запрещены. MCP-сервер работает только через stdio.
- **S5. Файлы.** Напрямую пишет только журнал (`AuditLog`). Чертёж сохраняется только в `SaveDwgHandler`, путь проверяет `PathGuard`: только имя файла, только папка из настроек, без `..`, дисков, сетевых путей и зарезервированных имён. Папка из настроек — только полный локальный путь: сетевые пути (`\\сервер\...`) и сетевые диски игнорируются, тогда используется `Документы\AutoCAD-MCP`. Без `overwrite` существующий файл не перезаписывается. Удалять файлы запрещено вообще.
- **S6. Лимиты.** Каждый запрос проверяется целиком до выполнения (`SpecValidator`). Лимиты из `Limits.cs`. Файл настроек может только уменьшить число объектов за вызов (`maxEntities`), остальные лимиты не настраиваются; тайм-аут настраивается в пределах 5–300 с. Запросы выполняются строго по одному, у каждого есть тайм-аут.
- **S7. Зависимости.** Только пакеты из `Directory.Packages.props` с точными версиями: `AutoCAD.NET` (официальный пакет Autodesk, только для компиляции, DLL AutoCAD в пакет не попадают), `ModelContextProtocol` (официальный SDK), `Microsoft.Extensions.Hosting`, пакеты тестов. Других источников NuGet нет.
- **S8. Никакого кода на лету.** `Assembly.Load`, `Reflection.Emit`, скриптовые движки запрещены.
- **S9. Никакого нативного кода.** `DllImport`, `unsafe`, `Marshal` запрещены.
- **S10. Реестр и окружение не трогаем.**

## Как работает проверка

Тест безопасности ищет запрещённые вызовы в тексте кода (комментарии и тексты сообщений не считаются, код внутри `{…}` в строках с `$` — считается). Он ловит обычные ошибки и попытки «в лоб», но это страховка, а не доказательство: хитро написанный код (например, через рефлексию) может его пройти. Главная защита — ревью Максима: любой новый код и все файлы из `.github/CODEOWNERS`.

Файлы с особыми правами или с правилами безопасности тоже под ревью Максима: `Core/Audit/AuditLog.cs` (единственный, кто пишет файлы), `Plugin/Handlers/SaveDwgHandler.cs` (единственный, кто сохраняет чертёж), `Core/Model/Limits.cs` и `Core/Settings/` (лимиты, S6), `Plugin/MainThreadDispatcher.cs` и `Plugin/PipeHost.cs` (тайм-ауты и `MCPSTOP`).

## Правила для агента-разработчика

- Не менять защищённые файлы: этот файл, `tests/AutocadMcp.SecurityTests/**`, `.claude/settings.json`, `.github/**`, `Directory.Packages.props`, `Directory.Build.props`, `global.json`.
- Файлы с особыми правами (список выше, «Как работает проверка») менять только по плану и с пометкой «⚠️ требует ревью Максима».
- Не отключать и не ослаблять тесты: никаких `Skip`, удалённых проверок и изменённых лимитов в тестах.
- Не добавлять пакеты.
- Новый инструмент добавляется по рецепту из `CLAUDE.md`. Добавление имени в `ToolNames.cs` проходит ревью Максима.
- Если правило мешает задаче, нужно остановиться и подготовить запрос Максиму (`/help-request`), а не искать обход.

## Человеческие предохранители

- **В AutoCAD:** каждое действие пишется в командную строку (`[Claude] build_drawing → OK (85 мс)`). `MCPSTOP` сразу выключает доступ: запрос, который ещё ждёт очереди, не выполнится, Claude получит ответ `connector_stopped`. `MCPSTATUS` показывает состояние. `MCPLOG` показывает, где журнал.
- **В Claude Desktop:** вызовы инструментов, которые меняют чертёж или пишут файл, по умолчанию требуют подтверждения. Не включай «разрешать всегда» для `save_dwg`.
- **Ctrl+Z** должен отменять вызов целиком (проверяется сценарием 4 на этапе 3).

## Настройка GitHub (один раз, делает Максим)

1. Settings → Rules → Rulesets → правило для ветки по умолчанию (`main`), Enforcement: Active:
   - Restrict deletions и Block force pushes;
   - Require a pull request before merging: 1 одобрение, Require review from Code Owners, Dismiss stale approvals;
   - Require status checks to pass: проверка `windows` (так называется задание в `.github/workflows/ci.yml`; `build-and-test` — имя всего workflow, его в списке проверок нет), Require branches to be up to date.
2. **Bypass list пустой.** Иначе тот, кто в нём есть, пушит в `main` мимо правил.
3. Проверка: прямой `git push` в `main` должен быть отклонён. Если прошёл — проверь bypass list.
4. Агент работает в ветке `dev`, в `main` попадает только через pull request с ревью Максима. Pull request открывается с GitHub-аккаунта коллеги: свой собственный pull request GitHub одобрить не даёт.

## Если нашли проблему безопасности

Нужно остановить работу и выполнить `MCPSTOP` в AutoCAD. Затем написать Максиму: что произошло, отчёт агента и журнал из `%LOCALAPPDATA%\AutocadMcp\logs\`. Пока Максим не ответит, коннектор не используется.
