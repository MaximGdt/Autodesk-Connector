# План работ

Агент ведёт работу строго по порядку. Галочки ставит **только** после проверки человеком. После каждого этапа делается коммит и тег `stage-N-done` (точка отката).

Легенда: 🤖 делает агент · 👤 делает или проверяет человек.

---

## Этап 0. Подготовка компьютера
**Цель:** на компьютере есть всё, чтобы собрать и запустить коннектор.

- [ ] 🤖 `/check-env`: проверить Windows, AutoCAD 2025 (полный, не LT), .NET 8 SDK, Git (и что он знает имя и почту автора), что папка — Git-репозиторий, Claude Desktop.
- [ ] 👤 Если проект пришёл ZIP-архивом (нет истории Git) — скачать его заново командой `git clone` по ссылке от Максима.
- [ ] 👤 Если Git не знает имя и почту — ввести две команды `git config --global …`, которые даст агент (агенту это запрещено).
- [ ] 🤖 Чего-то нет → дать человеку точную команду установки (`winget install …`) и после установки проверить снова.
- [ ] 🤖 Создать ветку `dev`.
- [ ] 👤 Для этапа 7 нужен свой аккаунт GitHub с правом записи в репозиторий (пригласит Максим) и вход в Git на этом компьютере. Не аккаунт Максима: свой pull request он одобрить не сможет.

**Готово, когда:** `check-env` пишет «ИТОГ: всё обязательное на месте».
**👤 Проверь:** в выводе нет строк `[НЕТ]`.

## Этап 1. Сборка и автотесты
**Цель:** убедиться, что готовый каркас собирается и проходит все проверки на этом компьютере.

- [ ] 🤖 `/build-test`. Исправления из ветки `fix` (16.11.2026) проверены в GitHub Actions: сборка без предупреждений, все тесты зелёные. На компьютере с AutoCAD это первый прогон. Если здесь сборка или тест красные, ничего не чини сам: сразу `/help-request` с полным выводом ошибки.
- [ ] 🤖 Коротко (5–7 строк) рассказать человеку, из каких трёх частей состоит коннектор и что проверяют тесты.

**Готово, когда:** сборка без ошибок и предупреждений, все тесты зелёные. Ожидается 76 в `Core.Tests` + 25 в `SecurityTests` (так прошло в GitHub Actions на ветке `fix`).
**👤 Проверь:** в отчёте агента «ошибок 0», «тестов не прошло 0».

## Этап 2. Первое подключение к AutoCAD и Claude
**Цель:** Claude впервые рисует в настоящем AutoCAD.

- [ ] 🤖 Собрать надстройку (AutoCAD перед этим закрыт).
- [ ] 👤 Открыть AutoCAD 2025, создать новый чертёж (Ctrl+N), ввести `NETLOAD` и выбрать DLL по пути, который даст агент. На вопрос о загрузке ответить «Загрузить один раз».
- [ ] 👤 Ввести `MCPSTATUS` → «Коннектор: РАБОТАЕТ».
- [ ] 🤖 `/live-test` → самопроверка (`--smoke`).
- [ ] 🤖 С разрешения человека подключить сборку к Claude Desktop (временная настройка для разработки, с резервной копией, см. `/live-test`).
- [ ] 👤 В Claude Desktop пройти сценарии 1 и 2 из `docs/ACCEPTANCE.md`.

**Готово, когда:** самопроверка «ИТОГ: ВСЁ В ПОРЯДКЕ», сценарии 1–2 прошли.
**👤 Проверь:** в чертеже появился прямоугольник на слое «Стены», в командной строке AutoCAD строки `[Claude] … → OK`.

## Этап 3. Больше типов объектов
**Цель:** Claude умеет многострочный текст, размеры, штриховку и вставку блоков.

Каждый пункт делается отдельно через `/add-tool` (это новые типы в `build_drawing`, имён инструментов не добавляется):
- [ ] 🤖 `mtext`
- [ ] 🤖 `dimension` (`linear`, `aligned`)
- [ ] 🤖 `hatch` (замкнутый контур, `SOLID`/`ANSI31`, масштаб)
- [ ] 🤖 `block` (вставка существующего блока по имени; атрибуты)
- [ ] 👤 Сценарии 3, 4 (Ctrl+Z отменяет весь вызов одним нажатием), 5.

**Готово, когда:** автотесты и самопроверка зелёные, новые шаги самопроверки укладываются в бюджет, сценарии 3–5 прошли.
**👤 Проверь:** размеры показывают правильные числа, штриховка внутри контура, один Ctrl+Z убирает всё нарисованное за один ответ Claude.
**Если Ctrl+Z убирает по одному объекту:** это важно, сообщи агенту. Он найдёт способ сгруппировать отмену (в пределах правил безопасности) или через `/help-request` спросит Максима.

- [ ] 🤖 `query_entities`
- [ ] 🤖 `list_blocks`
- [ ] 🤖 `modify_entities` (move / rotate / scale / set_layer / set_color / erase с лимитом 500)
- [ ] 👤 Сценарии 6 и 7.

**Готово, когда:** всё зелёное, сценарии 6–7 прошли, заблокированные слои не меняются (агент показывает тест).
**👤 Проверь:** изменилось ровно то, что просили, и ничего больше.

## Этап 5. Сохранение DWG
**Цель:** надёжное сохранение копии чертежа.

- [ ] 🤖 Проверить открытый вопрос из `docs/TOOLS.md`: после `save_dwg` открытый чертёж остаётся своим файлом. Если нет, подготовить исправление (`Wblock`) и пометить «⚠️ требует ревью Максима».
- [ ] 👤 Сценарии 8, 9, 14.

**Готово, когда:** файл появляется в `Документы\AutoCAD-MCP` и открывается, опасные пути отклоняются, перезапись только с разрешения.

## Этап 6. Упаковка для коллег
**Цель:** два файла, которые любой коллега ставит в два клика.

- [ ] 🤖 Поставить Node.js и Inno Setup (если `check-env` сказал «ПОЗЖЕ»), с согласия человека.
- [ ] 🤖 `/package` → `AutocadMcp-Setup-<версия>.exe`, `autocad-mcp-<версия>.mcpb`, `SHA256SUMS.txt`.
- [ ] 🤖 Убрать временную настройку разработки из Claude Desktop (вернуть резервную копию).
- [ ] 👤 Установить оба файла как обычный пользователь: закрыть AutoCAD → запустить установщик (Windows может предупредить о неподписанном файле, см. `docs/TROUBLESHOOTING.md`) → дважды кликнуть `.mcpb` → открыть AutoCAD («Всегда загружать») → сценарий 1.

**Готово, когда:** после установки из пакетов сценарии 1, 2, 8 проходят без `NETLOAD` и ручных настроек.

## Этап 7. Приёмка и передача
**Цель:** подтвердить, что всё работает хорошо и безопасно, и отдать на ревью.

- [ ] 👤 Пройти все сценарии `docs/ACCEPTANCE.md` (1–17).
- [ ] 👤 Поставить пакеты на второй компьютер или под другим пользователем Windows, сценарии 1, 2, 8.
- [ ] 🤖 С разрешения человека: `git push` ветки `dev`, открыть pull request в `main` с итоговым отчётом (что сделано, результаты тестов и самопроверки, список «⚠️ требует ревью»).
- [ ] 👤 Отправить Максиму ссылку на pull request.

**Готово, когда:** Максим одобрил pull request, проверки GitHub зелёные, изменения в `main`.
