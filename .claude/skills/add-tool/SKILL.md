# Добавить тип объекта или инструмент

Сначала реши, что это:
- **Новый тип объекта** для `build_drawing` (`mtext`, `dimension`, `hatch`, `block`): новых действий не появляется.
- **Новый инструмент** (`drawing_summary`, `query_entities`, `list_blocks`, `modify_entities`): это расширение возможностей, в отчёте обязательна пометка «⚠️ требует ревью Максима: новое действие».

Спецификация каждого — в `docs/TOOLS.md`. Если там чего-то не хватает, предложи вариант человеку одной фразой, а в отчёте отметь решение.

## Шаги (по одному, после каждого `/build-test`)

1. **Модель и проверка (Core).**
   - Тип объекта: поля в `EntitySpec` с `[Description]` (это читает Claude), имя в `EntityTypes`, правила в `SpecValidator`.
   - Инструмент: класс параметров в `Core/Model/` с `[Description]`, свой валидатор рядом.
   - Лимиты — только из `Limits` (новые лимиты добавляй туда со строгими значениями). `Limits.cs` под ревью Максима: в отчёте пометка «⚠️ требует ревью Максима».
   - Тесты в `tests/AutocadMcp.Core.Tests`: один хороший вход и **минимум три плохих** (пустое, за пределами, неправильный тип). Ошибки по-русски, с путём поля (`entities[3].height: …`).
2. **Выполнение (Plugin).**
   - Тип объекта: новый `case` в `BuildDrawingHandler.CreateEntity`.
   - Инструмент: файл в `Handlers/` по образцу `LayerHandlers` (чтение — `StartOpenCloseTransaction`, изменение — `StartTransaction` + `Commit`), регистрация в `ToolRouter`.
   - Заблокированные слои не меняются никогда. Ошибки — `HandlerException` с кодом из `ErrorCodes`.
   - Никаких вызовов команд AutoCAD по строке (`docs/SECURITY.md`, S1). Только объекты API.
3. **Инструмент для Claude (Server)** — только для нового инструмента: метод в `Tools/AutocadTools.cs`. `ReadOnly = true` для чтения, `Destructive = true` для удаления и перезаписи. В описании: что делает, когда вызывать, лимиты.
4. **Список действий** — только для нового инструмента: имя в `Core/ToolNames.cs` и в `packaging/mcpb/manifest.json`. Тест безопасности проверяет, что все три списка совпадают.
5. **Документация:** `docs/TOOLS.md` (статус ✅), сценарий в `docs/ACCEPTANCE.md`.
6. **Самопроверка:** шаг в `src/AutocadMcp.Server/Smoke/SmokeTest.cs` с бюджетом и такой же строкой в таблице бюджетов `docs/ACCEPTANCE.md`. Для изменяющих инструментов добавь и шаг «опасный ввод отклоняется».
7. `/build-test` → `/live-test` → отчёт по шаблону.

## Как проверить себя перед отчётом

- Плохой ввод не меняет чертёж (тест на валидатор + шаг самопроверки).
- Один вызов — одна транзакция — один Ctrl+Z.
- 1 000 объектов укладываются в бюджет.
- Описание для Claude однозначное: прочитай его как Claude, которому надо нарисовать план комнаты.
