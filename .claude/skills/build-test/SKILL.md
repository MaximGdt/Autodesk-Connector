# Сборка и автотесты

1. Если меняется надстройка (`src/AutocadMcp.Plugin`) **или ядро** (`src/AutocadMcp.Core`: его DLL лежит рядом с надстройкой), убедись, что AutoCAD закрыт. Иначе DLL заблокирована и сборка упадёт с «file is being used by another process». Спроси человека: «Закрой, пожалуйста, AutoCAD (сохрани свои чертежи), напиши "готово"».
   То же с MCP-сервером: после подключения к Claude Desktop (этап 2) Claude Desktop держит `autocad-mcp-server.exe` и `AutocadMcp.Core.dll` рядом с ним открытыми. Если меняется `src/AutocadMcp.Server` **или** `src/AutocadMcp.Core`, попроси полностью закрыть Claude Desktop (значок в трее → Выход).
2. Сборка (предупреждения считаются ошибками):
   ```
   dotnet build AutocadMcp.sln -c Release
   ```
3. Тесты:
   ```
   dotnet test AutocadMcp.sln -c Release --no-build
   ```
4. Разбор результата:
   - **Всё зелёное** → коротко: «Сборка: ошибок 0. Тесты: пройдено N, не прошло 0.»
   - **Ошибка компиляции или обычный тест** → исправь причину в своём коде. Тест не трогай, если он проверяет правильное поведение. Три неудачные попытки → `/help-request`.
   - **Красный `AutocadMcp.SecurityTests`** → в коде появилось запрещённое. Сообщение теста называет правило (S1–S10), файл и строку. Убери запрещённый код. **Никогда** не меняй тест, не ставь `Skip`, не переписывай код так, чтобы «обойти» шаблон: это хуже, чем красный тест. Если задачу нельзя решить без запрещённого API → `/help-request`.
   - **Медленный тест (`PerformanceTests`)** → ищи лишние циклы и аллокации в своём изменении. Бюджеты не поднимай.
5. Человеку объясняй простыми словами: что сломалось, что ты поменял, что теперь зелёное. Названия тестов — только если человек спросит.
